# 湖财人使用与运营手册

本手册面向前台用户、组织与企业管理人员、保卫核验人员及后台运营人员。功能说明以本仓库实现为准；入口是否出现，还取决于模块开关、账号状态、实名状态和实际授权。部署与多端编译请从 [项目 README](../README.md) 进入相应文档。

> 仓库中的页面和接口不等于某个学校、支付渠道或第三方服务已经接入。新部署环境必须完成自己的配置、授权与验收。不要使用生产人员资料进行公开演示，也不要把账号、临时密码、证件、聊天记录或后台截图提交到 GitHub。

## 1. 先理解账号与身份

平台账号和学校统一认证账号是两套凭据。学校统一认证用于核对身份；日常使用湖财人时，使用独立的平台用户名和密码。

| 状态或角色 | 含义 |
| --- | --- |
| 未登录用户 | 可访问开放的内容；个人记录、聊天和提交动作仍受权限保护 |
| 已登录、待实名人员 | 已有平台账号，但不能据此认定为学校实名成员 |
| 已实名人员 | 身份已通过学校认证或授权人工复核；来源会被保留 |
| 平台运营账号 | 用于后台工作；后台账号本身不等同于通过学校实名校验 |
| 全局管理员 | 管理账号、系统配置及授权，并访问被允许的内部管理功能 |
| 板块/记录管理员 | 仅在被授予的资源、记录和操作范围内工作 |

账号可被暂停或注销；需要首次改密的账号，在完成改密前不能正常使用受保护业务。没有内置的通用正式管理员账号可供直接登录。

### 1.1 新用户通过学校认证注册

1. 在登录页选择新用户实名注册。
2. 进入学校官方认证页面，在学校页面完成认证。
3. 返回平台核对学校返回的姓名、学院/部门及已获准下发的身份字段。
4. 若该身份已有平台账号，使用原账号登录，不重复注册。
5. 若没有平台账号，在有效的一次性注册凭证内设置平台用户名和密码。

学校未下发的字段不会被系统推算成真实资料。认证配置未启用、必要身份字段缺失、回调不匹配时，应联系管理员处理，不能用页面手工输入替代学校认证结果。

当前注册安全回跳实现以 H5 浏览器绑定为基础。App/小程序不能直接复用 H5 绑定；相应业务域名、Universal Link/App Link 或平台回跳尚未完成验收时，服务端会拒绝该端首次认证注册。此时先在正式 H5 完成注册，再按目标端验收结果开放使用。

### 1.2 无学校数字账号的老校友

1. 选择“老校友人工实名认证”。
2. 填写真实姓名、学院、专业、入学与毕业年份、联系电话和情况说明，提交本人证明材料并确认用途授权。
3. 本机保存申请查询凭证；重新进入同一页面可继续查看进度，页面停留期间也会刷新状态。
4. 管理员可开始复核、要求补充材料、通过或驳回；需要补充时按说明重新提交。
5. 审核通过后点击“继续设置平台账号”。系统先检查身份是否已有关联账号，再引导注册或登录。

审核通过不代表平台账号已自动创建。不要清理申请查询凭证后再期待系统自动识别原申请；查询凭证丢失时联系授权管理员核实。当前实现以本页状态和平台通知为主，不应承诺未配置的短信或邮件送达。

### 1.3 后台录入人员

后台可单个新增普通人员，也可使用专用 Excel 模板导入。导入先预览格式及重复情况，再确认提交；用户名和可验证学工号会与现有人员及本批数据校对。

已核对真实材料的管理员可按界面要求填写依据并确认人工核验。对已录入但待实名的普通人员，也可使用账号管理的人工校验入口。该操作不能覆盖已有实名结论，不能把运营账号或演示账号改造成正式实名人员，也不能绕过已存在的身份冲突。

临时密码应通过受控渠道交给本人。首次登录需要修改密码，不要将临时密码写在备注、工单正文或公开仓库中。

### 1.4 日常登录与密码管理

- 同一客户端设备标识的有效登录可持续保留，不按固定时长自动过期；清理浏览器存储、退出登录、账号停用或改密仍会导致重新登录。
- 换设备登录会撤销旧设备的会话；不同浏览器配置、无痕窗口或清理存储可能被视为不同设备，而不是硬件级身份识别。
- “我的 → 我的资料 → 账号安全 → 修改密码”用于本人改密，需要验证当前密码；完成后重新登录。
- 全局管理员可在“账号管理”中对单个正常账号设置临时密码，填写原因并核对目标；旧登录会失效，本人下次登录需再次改密。

## 2. 普通用户常用功能

### 2.1 个人资料与校友编号

“我的资料”区分学校/人工已核验资料和个人补充信息。专业、班级、入学年份、毕业或预计毕业年份为只读字段；学籍错误应重新校验或联系管理员，不要通过个人简介绕开纠错流程。

所在城市从行政区域库选择；联系电话、邮箱、个人简介可按界面保存。个人补充资料不会因此自动公开到校友名录。资料页通常显示脱敏学工号；本人身份卡可读取系统已保存的完整学工号，历史数据未保存原号时不能从脱敏值还原。

校友编号由全局管理员单独或批量下发。批量范围是所有正常、已实名、非演示且尚未有编号的人员，含符合条件的在校生和教职工，不限于“校友”身份。已有编号保持不变。

### 2.2 消息与办理进度

“对话”顶部保留消息与办理进度入口，集中查看本人通知、审核意见和办理结果。活动报名、返校申请等业务的进度，以服务端记录为准；提交成功不是审核通过或现场办结。

### 2.3 湖财圈：校园墙、话题和评论

在湖财圈发布页输入内容，可选择/创建话题、提及人员、添加图片；帖子和评论可选择匿名展示。匿名昵称与头像仅改变前台呈现，后台保留真实作者关联用于授权管理，不能把它理解为不可追溯的匿名通信。

正常实名用户的发帖、评论及组织留言按当前规则直接发布，无需逐条预审。服务端敏感词保护、权限检查仍会执行，管理员可填写原因下架；关闭模块或暂停账号也会影响使用。业务申请的审批不因此取消。

校园墙焦点轮播用于管理员置顶内容和符合规则的热门帖子，不是全部新帖列表。评论、点赞、举报、收藏等以页面实际提供的操作和返回状态为准。

### 2.4 对话与群聊

在“对话”中搜索已有会话或发起对话，可发送文字、图片、文件和已发布的表情包。桌面 H5 提供可见窗口右下角的浮动对话入口，移动端使用对话页。

| 群类型 | 创建/加入方式 | 退出与管理 |
| --- | --- | --- |
| 固定学院群、专业群、班级群 | 根据正常已实名学生/校友的明确学籍字段自动关联；资料不足则不推测创建 | 不可主动退出或解散，不允许随意增删不匹配成员；后台可指定群主，群主可设置管理员 |
| 用户自建群 | 用户创建并按权限管理成员 | 普通成员可退出；群主可解散。群主不能以普通退出动作遗弃仍有效的群 |

固定群名称只展示对应学院、专业或班级名称；匹配键仍包含必要的学籍范围，避免同名专业或班级错误合并。资格变化后成员关系会重新核对。

单个聊天文件代码上限为 5 GiB（界面标记 5GB），采用分片上传；存储总配额、并发限制、浏览器/小程序能力、网速和反向代理配置可能更早限制上传。超大文件须在目标客户端和正式网络另行验收，不能仅凭上限文案承诺所有端都能上传 5GB。

聊天不是端到端加密系统。具有专门后台权限的全局管理员可以检索会话、查看消息及附件，并隐藏消息或暂停会话；管理员身份不会自动使其成为聊天参与者。部署方应明确告知用户管理范围、数据保存周期和使用目的。

### 2.5 校友组织

组织分类包括同年级、同班、同专业、同兴趣、地方、学院和行业。依据明确且符合条件的资料，系统可创建并关联组织；学籍类不解析班级名称来猜测专业/年份，城市、兴趣、行业类也需要已有的明确数据。

进入组织主页可查看简介、联系、成员、相册、留言以及组织发布的活动/事项。快捷入口进入对应独立页面；加入申请、退出及管理动作仍按该组织权限与状态处理。

组织相册支持符合实名权限的用户新建相册和上传照片，不限组织管理员；编辑、删除自己的相册/照片与管理他人内容使用不同权限。单张图片上限按页面与服务端验证执行，当前通用图片限制为 500 MiB（界面标记 500MB），还需通过格式检查和存储限制。

**组织成员资格与固定聊天群不是一回事。** 自动组织中用户主动退出或被移除的状态会被记录，不应自动反复加回；固定学籍聊天群则由已核验学籍决定，不能自行退出。

### 2.6 企业认证、招聘与资源

1. 正常正式实名用户进入“企业主工作台”，填写营业执照企业全称、统一社会信用代码、行业、地区、介绍、联系人及要求的证明材料。
2. 若管理员配置并启用已获授权的企查查接口，可按完整企业名称查询登记资料。只有完全匹配结果才用于辅助填充，缺失或错误字段由用户核对补充。
3. 提交后进入后台审核。接口查询成功不代表企业认证通过；未开通、额度不足或查询失败时仍可手工填写。
4. 审核通过且企业仍处于有效状态后，申请人通过本人绑定的企业工作台维护资料、提交本企业招聘信息。
5. 招聘发布状态和审核意见在相应业务记录中查看；企业主权限不允许操作其他企业或任意跳过后台审核。

合作广场用于资源需求/供给；导师、课堂、权益与志愿服务按已发布项目提供浏览及相应申请。联系人绑定、报名审核、名额和发布状态，以各页面结果为准。

### 2.7 活动、返校预约与身份核验

活动详情可提交报名；返校预约填写日期与事由后等待办理。身份卡的动态码由服务端签发，页面每 5 秒更新，码本身使用短有效期；截屏不应作为长期通行凭证。

保卫核验流程：授权人员登录同一平台 → 选择站点 → 扫码或输入临时码 → 核对人员信息 → 明确确认放行/拒绝并记录说明。扫描得到预览不等于已经放行；系统保存核验人员、站点和处理记录。实际闸机硬件联动不是这套扫码确认流程自动附带的能力。

### 2.8 回馈母校与证书

前台提交的是公益捐赠意向，不是支付订单，也不构成到账证明。实际款项通过学校正式渠道办理。

后台有权人员核对真实到账金额、日期和学校回执号后，执行“确认到账并签发证书”；服务端生成唯一证书编号。用户可在本人办理记录/证书页面查看结果。校内人员档案中的“捐赠联系记录”仅供关系维护，不会增加财务到账、改变捐赠审批或签发证书。

### 2.9 同城地图与行政区域

内置底图为长沙及周边街道数据，支持缩放、平移和学校主校区标注。其他区域需由管理员另行提供合适的地图资源；不能将行政区域 JSON 库理解为全国街道底图。

校友分布来自符合公开条件的名录城市聚合，用城市中心点和人数展示。它不是个人 GPS、街道住址或实时位置，不会把某个城市中心点当成个人坐标。底图覆盖范围以当前已发布地图为准。

## 3. 组织、企业与保卫管理人员

### 3.1 组织管理

全局管理员按组织记录授予查看、修改、审核或成员管理权限。有对应权限的人员从组织管理入口维护本组织内容，发布活动/公告及处理成员事项；权限不足的动作不会因为页面入口可见而通过接口。

授权可到期或撤销，子授权会随父授权失效。组织发布还取决于组织已发布状态及相应操作权限；请在自己组织范围内工作，不要复用全局管理员账号。

### 3.2 企业管理

企业主是认证申请通过后与企业记录绑定的人员，不等同于后台全局管理员。企业被停用、下架或认证状态变化时，工作台能执行的动作也会变化。变更申请人或企业主体应走明确的管理与核验流程，不能仅改显示名称代替关联。

### 3.3 门岗管理

全局管理员可配置保卫负责人；负责人按授权管理站点和保安人员。普通扫码人员只能执行自己的核验职责，不能因此查看其他全部后台数据。授权被撤回、账号停用或会话被替换后应停止使用原页面并重新核对身份。

## 4. 后台管理员操作指引

### 4.1 首次运营建议顺序

1. 确认生产部署、备份、HTTPS、域名及管理员访问已经由运维验收。
2. 核对“学校实名校验配置”，按真实 CAS/OIDC 对接资料设置并执行连通/参数检查；检查成功后才启用。
3. 在“模块管理”中只开放准备好运营的模块。
4. 完善行政区域、敏感词、校历、服务目录、公告、组织等基础内容。
5. 创建/导入人员，处理实名资料与重复冲突，按最小职责授予管理员权限。
6. 用隔离测试账号完成注册/登录、申请/审核、发布/下架、聊天、上传、证书与门岗核验等目标流程验收。

### 4.2 账号管理

- 使用关键词、状态、学院→专业→班级、身份类型、认证状态及年份筛选人员。
- 下载专用 Excel 模板，以文本方式填写学工号等标识，先预览错误和重复项，再确认导入。不要简单“覆盖导入”替代身份冲突处理。
- 单个新增普通人员和新增运营账号有不同用途；运营授权与学校实名标志分开管理。
- 人工核验需核对原始资料、完整学工号和依据，不是无条件切换“已认证”。
- 校友编号批量下发先预览范围，再二次确认；不覆盖现有编号，数据已变化时重新预览。
- 修改密码、暂停、注销、授权等动作应核对目标人员，填写界面要求的原因并查看结果。

### 4.3 内部人员档案

在账号行点击“查看人员信息”进入校内维护页。全局管理员可维护联系资料、教育/工作经历、标签、内部备注、供需、合作、活动、捐赠联系、跟进和校友关系记录。

档案区分源业务记录与内部补充记录：补充备注不更改学校核验字段，不修改本人前台资料，不改变业务审批、支付或证书状态。完整学工号查看要求记录原因并短时显示。最后的“资料概览”是已有记录的汇总，不是调用外部模型生成的 AI 推断；不要将内部标签与关系备注导出公开。

### 4.4 模块开关

“系统与审计 → 模块管理”由全局管理员控制。关闭后对应前后台入口和相关资源不可见，相关业务 API 也受服务端限制；关闭不是删除数据，重新开启后恢复符合权限和发布条件的内容。

账号与身份、审计/模块恢复入口及基础保护能力不能随业务模块一起关闭，以免无法登录或恢复。关闭公告运营不等于删除本人办理通知；关闭业务模块也不应被当作清除历史审计的方式。完整目录见 [模块与权限说明](MODULES.md)。

### 4.5 内容、对话与审计

- 公告、活动、岗位等可按草稿/发布/下架流程维护；业务申请按类型审批或办理。
- 实名公开发言直接发布后，管理员可因明确原因下架/恢复；敏感词由服务端检查，不能只在前端拦截。
- 对话管理可按会话、发送人、类型、日期等筛选；隐藏消息/暂停会话需填写原因。解散的自建群保留历史，不能按“启用会话”复活。
- 表情包后台维护与发布后才供前台选择，提交前确认素材授权。
- 审计记录包含操作类型、主体、请求信息、IP、设备/浏览器解析和可得的 IP 归属地。IP 归属地是数据库估算，VPN、代理、运营商出口和内网会影响结果，不能作为精确地点或 GPS 证明。

### 4.6 项目证书模板

在公益项目管理中选择项目，打开证书模板编辑，设置支持的版式、颜色、标题、感谢词、签发单位及背景图，预览后保存。感谢词支持 `{recipientName}`、`{projectTitle}`、`{amount}`、`{donatedAt}` 四种变量。

这是受约束的模板编辑器，不是任意 HTML/脚本画布。签发时保存模板快照，后续更改项目模板不应改写历史已签发证书；签发前仍需独立核对真实到账与回执。

### 4.7 区域和地图维护

行政区域库支持导入预览、校验、确认应用及导出；地区代码的父子关系和启用状态会影响前台选择器。地图管理支持符合格式要求的 PMTiles 底图上传及发布、GeoJSON 图层绘制/维护与发布。预览成功不代表自动获得地图数据许可；应保留来源、坐标系、授权与署名，并在目标范围验证道路和标注。

## 5. 常见问题与反馈资料

| 情况 | 首先检查 |
| --- | --- |
| 未看到某模块/管理按钮 | 模块是否开启、账号是否正常、实名是否通过、是否完成首次改密、是否有该记录的操作权限 |
| 提交或保存出现版本冲突 | 重新加载记录，核对他人修改后再提交；不要盲目重复请求 |
| 已在学校认证但平台仍不能注册 | 同一 H5 浏览器的 Cookie、有效回调、字段映射和身份重复状态 |
| 人工审核通过但还不能登录 | 是否完成“继续设置平台账号”；是否应使用已有平台账号 |
| 学籍群未生成 | 身份须符合条件，学院/专业/班级/入学年份等必要字段须明确；不从文本猜测缺失字段 |
| 附件无法上传 | 格式、单文件限制、总配额、同账号并发、代理请求配置、客户端文件能力和网络 |
| 地图空白或仅有部分范围 | 当前已发布底图覆盖、地图资源请求、浏览器 WebGL、缓存与部署路径 |
| 企业资料无法自动填充 | 授权接口是否启用、完整企业名称是否匹配、额度、第三方返回；可先手工核对填写 |
| 证书未出现 | 是否实际到账并由授权人员签发，不能只看意向状态或联系备注 |
| 旧设备突然退出 | 是否在其他设备登录、改密、退出、停用或清理存储 |

反馈时提供功能入口、发生时间、脱敏错误信息和可重复步骤。公开 Issue 不要携带真实账号凭据、完整学号/证件号、电话、用户照片、聊天正文、申请材料或服务器密钥。
