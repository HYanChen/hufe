# 持久登录、单设备登录与访问限流

## 用户可见规则

登录成功后，当前浏览器保持登录；刷新、关闭后重新打开和服务器重启不按固定时间强制退出。相同浏览器安装标识再次完成真实密码登录，可保留已有标签页的登录。其他设备成功登录时，旧设备的全部登录凭证失效。

主动退出、本人修改密码、管理员重置密码、暂停或注销账号都会结束原登录。账号重新启用后，旧登录不会恢复，需要重新输入密码。错误密码不会将当前用户踢下线。“保持登录”不等于一直处于在线状态；没有以持久会话伪造实时在线人数或活动时间。

本次从旧版内存登录升级时，旧进程里已有的会话无法凭空迁移，可能需要重新登录一次；通过新版登录签发的凭证才具有跨重启能力。

## 客户端合同

- `POST /api/v1/auth/login` 保留用户名、密码参数，增加 `deviceId`。设备标识由客户端随机产生并持久保存，不使用 IP、定位、浏览器敏感指纹识别设备。格式为 16–128 位字母、数字、下划线或短横线。
- 登录返回原有 `accessToken`、`tokenType`、`user`；`expiresAt` 为 `null`，`sessionPolicy` 为 `{persistent:true,singleDevice:true,expiresAutomatically:false}`。没有额外刷新令牌，也不保存密码用于自动重新登录。
- 原客户端未传设备标识仍需完成密码认证，服务器将此次登录视为新设备。设备标识不是密码、令牌或免认证依据。
- 前后台共享同源浏览器安装标识。不同浏览器、隐私窗口或不同源的存储空间是不同安装；不通过个人指纹推测它们属于同一物理设备。
- 客户端通过 `/api/v1/me` 恢复和定期检查真实登录状态；收到明确认证失效码 `SESSION_REPLACED`、`SESSION_REVOKED`、`CREDENTIALS_CHANGED`、`ACCOUNT_INACTIVE` 或 `ACCESS_TOKEN_EXPIRED` 才清除凭证。网络错误和服务端暂时故障不应直接清除登录。

## 服务端约束

`application-data.json` 的 `authDeviceSessions` 只保留账号关联、随机会话 ID、设备 HMAC、令牌 SHA-256、凭据版本和真实登录时间，不保留原始长期令牌、密码或设备 ID。每账号仅一个活动设备，同设备最多保留 32 个登录凭证。只记录有限的撤销令牌哈希和原因；它们不能用来还原或重新签发令牌。

上述 JSON 文件名属于本次历史实现记录；现行 MySQL 模式将同一 `authDeviceSessions` 逻辑集合保存于 `application` 命名空间，不再读写该旧业务 JSON 文件。

每次认证都重新检查当前持久会话、账号状态和 `credentialRevision`。密码验证成功后，签发事务仍核对最新凭据版本；更早开始却更晚完成的登录不得抢回已成功的新设备。退出只撤销对应活动会话，旧设备迟到的退出不影响新设备。数据库落盘成功后才发布新会话，失败不撤销旧设备。

保留的同步 `issueAccess()` 仅供原有内部隔离测试夹具使用；真正 HTTP 登录统一走持久 `issueLogin()`，不使用该内存测试路径。

## 限流

保留默认每分钟 180 次上限和具体接口的更严格或更高频上限。已认证请求以服务端验证得到的账号加读写类别区分，显式配置的接口按规范化路由单独计数；地图查看资源共用受限资源桶。登录及其他认证入口仍按可信来源 IP 限流，客户端不能通过伪造设备 ID 或用户 ID 绕过。请求过频返回中文 `RATE_LIMITED` 提示，不让同一校园出口下正常用户互相消耗账号配额。

## 验证

新增 7 项持久会话测试和 2 项限流测试，通过真实 HTTP、临时数据库重启、并发签发/撤销及写盘失败验证上述约束；管理员改密另有 9 项测试，包括真实持久登录撤销与服务重启后的拒绝。全部已纳入最终 238/238 后端全量通过结果。

独立客户端验收脚本已完成真实双浏览器登录、同设备重登、错误密码不踢人、异设备踢出提示、前后台刷新免登录；在暂停测试后实际关闭并以原临时数据库重启 API，当前设备前后台令牌仍返回 200、旧设备仍返回 `SESSION_REPLACED`，无浏览器脚本异常。所有测试只使用隔离数据，不修改正式账号。
