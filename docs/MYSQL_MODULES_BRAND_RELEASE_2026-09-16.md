本说明记录版本 `20260915T175805Z-8992df7e` 的实现机制和历史验收结论；公开版不包含生产数据库名称、备份位置或业务记录数量。2026-09-16 已完成 MySQL 切换及部署执行、在线健康检查、账号完整性与静态文件校验。这些历史结果不代替其他环境的部署验收。旧文档中的 PostgreSQL 迁移示例不适用于本次 MySQL 切换，不要在 MySQL 上执行旧的 PostgreSQL SQL 文件。

## 1. MySQL 数据边界与切换

- `DATABASE_DRIVER=mysql` 时，真实业务状态使用 MySQL。`application` 保存账号、业务、身份、模块开关与人员补充档案；另有 `chat`、`image-transfers`、`audit`、`regions`、`content` 五个命名空间。
- 上传文件、地图底图和图片等二进制资产仍由持久目录保存；MySQL 保存其业务关联与状态。这些持久目录必须连同数据库一起备份。
- 当前适配器使用单写入进程约束。不要为同一组数据库表启动第二个 API 写入实例；数据库失联不能回退写入旧 JSON。
- 一次性切换脚本为 `scripts/mysql-baota-update.sh`。它在维护窗口停止原服务后读取服务器自己的生产文件，准备六份快照，再导入并逐份哈希核验。禁止使用开发机数据覆盖正式人员、密码和业务记录。
- 目标数据库必须为空。失败留下的非空数据库须先核查，不得自动清空重试。保留旧容器、数据库备份、静态站点及持久目录备份。
- 发布目录按完整文件清单严格验证。运行日志必须输出到发布目录之外的受保护日志目录；不要在解压后的发布目录中创建 `update.log` 等额外文件，否则预检查会正确拒绝运行。
- 放开业务流量之前可按脚本恢复旧服务；一旦新 MySQL 已接收用户写入，不能直接切回旧 JSON，以免丢失更新。
- 原 JSON 开发账号创建、JSON 官网同步和旧地区升级入口在 MySQL 模式会拒绝执行。日常新增/改密/地区维护使用后台接口；迁移使用 `server/src/cli/mysql-data.js` 和 `prepare-mysql-snapshots.js`。

### 请求审计的性能、完整性与故障恢复

- 请求审计使用专用增量追加路径，不再为每次请求复制、序列化或计算全部历史记录。启动时建立 SHA-256 流式状态，正常单条追加固定执行 5 条查询/写入语句，另有事务开始与提交；只新增一行审计及更新集合数量、修订号和快照校验值。1.2 万条历史记录的测试禁止访问旧数组条目与迭代器，以验证该路径没有隐藏的全量扫描。
- 增量结果与原完整规范化 JSON 快照的 SHA-256 完全相同，不使用降低校验强度的摘要替代。导出、备份与只读校验仍从 MySQL 逐行重建并核验完整快照，保留未知字段、数组顺序及字符串类型。显式维护或裁剪历史记录后，下一次追加会重建增量状态。
- 只有收到 MySQL 提交成功确认后才发布内存状态。连接失效、修订号冲突或提交结果不确定时停止使用该写入连接，不自动重连或回退 JSON；重启后以 MySQL 已提交数据为准。
- 审计追加失败后，已经完成的业务响应保持原结果，不在响应发送阶段改成可诱发用户重试的 503。系统立即阻止后续 API 请求，并尝试把失败请求及已在途请求保存到主业务 MySQL 的 `auditRecoveryRequests` 恢复队列。健康检查及 OPTIONS 不受该守卫拦截；已被守卫拒绝的请求不再追加失败审计，避免故障洪泛。
- 恢复队列不是 JSON 回退。重启初始化时，先比对并补回审计记录，再清除对应恢复项；若相同编号已经存在，必须完整记录一致才按已提交处理，不会重复追加。编号冲突、记录不一致或队列损坏会阻止启动，原恢复记录保留。
- 若主库恢复写入也未收到成功确认，不能断言记录已经丢失或无法恢复：原审计或主库的 COMMIT 均可能已执行。状态明确标记 `recoveryUncertainFailures` 与 `recoveryDurability=unknown-manual-verification-required`，继续保持降级与请求拦截，要求人工核验。旧 `unrecoverableFailures` 仅作兼容计数别名，不代表已证实的永久丢失。错误日志仅包含 requestId 与固定说明，不输出驱动错误、SQL 或业务内容。

## 2. 模块管理

入口：后台“系统与审计”中的“模块管理”，仅全局管理员可变更。每次变更必须填写 5 至 300 字原因，使用配置版本检查；其他管理员先保存时会提示重新核对，不覆盖新配置。

可分别控制的 21 个模块：湖财圈、对话、公告与消息运营、官网资讯同步、校友组织、校友名录、同城地图、活动、返校预约、返校身份核验、服务办理、校历、意见反馈、校友企业、岗位招聘、合作广场、校友导师、校友课堂、校友权益、志愿服务、回馈母校。

关闭模块后：

- 前后台导航入口隐藏，业务接口拒绝访问；保存的旧链接、发布接口、评论接口和附件业务接口不能继续操作。
- 混合申请列表在分页前过滤，数量和分页一致；首页、摘要、组织主页、消息与未读数不夹带已关闭业务内容。
- 关闭“服务办理”只影响服务目录和服务申请，不关闭“全部服务”导航页。身份卡仍可查看身份资料；关闭返校核验时不提供核验功能。
- 校友名录和地图独立控制；关闭名录不关闭地图的城市聚合与定位。
- 不删除账号、记录、群聊、申请、文件或模块配置。重新启用后恢复已有数据。已下载到用户设备的文件不会被远程删除。
- 服务端写入拦截即时生效。已经打开的 H5 页面通过配置刷新/前后台导航更新可见状态；短暂断网时保留最后确认的配置，不把网络错误当作“关闭全部功能”。
- 已打开的服务说明和企业招聘列表在对应模块关闭后清除，迟到请求及旧确认弹窗不能恢复入口或继续提交。校园墙编辑页被关闭模块导航离开时，仅为当前本人会话保存本机草稿，不自动发布；草稿附件只保留图片 ID，不保存临时图片地址或凭据。

始终保留：账号与身份、个人资料、修改密码、实名校验、系统审计、模块管理、行政区域库和敏感词保护等基础能力，避免关闭后无法登录或恢复。基础能力中的身份通知仍可查看。

模块停用不同于账号授权、内容下架或数据删除；这三类操作仍有各自权限与审计，不可互相代替。

## 3. 人员档案边界

账号管理提供独立人员档案，包含基本资料、标签、资源供需、企业合作、活动、公益捐赠、跟进、关联人员和资料概览。系统产生的业务记录按账号 ID 关联，不按姓名拼接；同名人员不能被合并。

管理员补充教育、工作、联系方式、标签、校内记录与跟进内容，保存到真实数据库并记录审计。补充资料不自动覆盖学校校验学籍，不修改账号密码/身份/权限，也不代替报名、签到或财务到账记录。业务关联记录与校内补充记录应分别显示来源。完整学工号需要授权管理员填写查看原因后单独读取。

“资料概览”是依据已有记录形成的事实汇总，不冒充已接通的 AI 服务；没有实际记录的内容保持空态。公益参与意向、校内补充金额不能计入学校确认到账总额。

## 6. 发布保护与验收结论

本节保留可复用的部署约束和历史验证结果；实际数据库标识、服务器目录、备份清单及业务数量由授权维护人员单独交接。

- 只读容器启动前必须准备持久数据挂载点。发布包显式包含 `server/data/.mountpoint`，不携带开发机业务数据；维护前以实际运行用户、只读根目录及嵌套挂载进行预检查。独立 Linux 容器验证了真实 API 健康检查 200，相关打包与部署回归通过。
- 迁移目标必须为独立空库；目标已存在但没有完整准备记录时拒绝继续，绝不自动删除失败库或覆盖非空数据库。维护前保留原环境文件、数据库完整备份和校验值。
- 非 root 进程需要能够读取公开依赖。仅在依赖解压子 shell 使用 `umask 022`，环境文件、备份和日志继续使用私密权限。原生 Linux 临时卷回归确认依赖目录和普通文件可由运行用户读取，私密探针权限仍为 600；随后在只读挂载下成功导入 `mysql2/promise`、应用模块并启动真实 API。不能用开发机共享目录的权限模拟替代目标系统验证。
- 本次历史上线已完成六个命名空间的冻结快照导入、逐一核验及回读导出；账号字段、身份、权限、凭据、会话、对话和审计记录保持完整。没有使用本地测试账号替换生产账号，也没有批量改密或重置模块。
- 对外入口只代理必要的 API，数据库不直接向公网开放。只读验收确认 `/health` 使用 MySQL，后台账号、审计、模块接口在未登录时返回 401，前后台 HTML 及初始 JS/CSS 与发布包逐字节一致；地图字节范围请求亦完成验证。
- 品牌接口返回 `Hunan College of Finance and Economics`；组合标识、校徽及中英文字标三份资产完整 SHA 与原件生成的包一致，后台登录页已通过视觉检查。
- 验收仅在隔离数据中进行写入测试，测试数据不导入生产。新 MySQL 已接收业务写入后，禁止直接恢复旧 JSON；需按数据库备份与恢复方案处理后续故障。

上述结果针对记录版本，不表示后续下载者的新环境已验收。请按当前发布包的部署说明重新检查运行时、私密配置、数据迁移、资产校验与账号权限。
