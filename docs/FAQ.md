# 常见问题与排查

本页针对当前代码和交付方式。排查时先记录版本、现象、复现步骤和脱敏错误，不要在公开 Issue 中粘贴密码、令牌、身份证明、私有聊天、完整数据库或运行环境文件。

## 获取与启动

### GitHub 的 Source code ZIP 能直接放到宝塔运行吗？

不能。GitHub 自动生成的 Source code 是源码快照，不是包含构建结果和运行依赖的完整版。运维交付请选择 [Releases](https://github.com/HYanChen/hufe/releases) 中维护者上传的完整部署 ZIP 与配套 SHA 文件；自行构建从[开发指南](DEVELOPMENT.md)开始。

### 为什么没有默认管理员账号和密码？

公开仓库不带生产账号或密码。已有系统迁移应保留原正式账户与权限；新站需要合法初始数据和受审计的首管理员初始化方案。当前没有通用生产 `bootstrap-admin` CLI，不要在生产切成开发模式运行 `create-dev-*`。

### 页面打开了，但内容为空或登录失败？

静态站、API、数据库是三个独立层次。先检查 API `/health`，再看浏览器请求是否指向正确网关，确认返回 JSON 而不是 `index.html`；之后再检查数据库就绪、账号状态和模块设置。不要因首页可见就判断后端已部署。

### `node_modules/.bin/uni` 不存在？

在仓库根目录完成 `pnpm install --frozen-lockfile`，确认 Node/pnpm 可用。用户端源码就在仓库根目录，脚本会以当前工作目录作为输入；不要在 `pages/` 或 `admin/` 中启动用户端构建。

### 本地调试会修改正式数据吗？

取决于实际 API 和数据库配置。测试应使用隔离目录、隔离 MySQL 库和测试账号，不要把生产密钥复制到 `.env.local`。`*-qa-*` 脚本可能创建、清理或重置测试数据，运行前必须读脚本和环境边界。

## 部署与数据库

### 发布包 SHA 不匹配怎么办？

停止解压/部署，确认 ZIP、`.sha256` 和 release 属于同一版本，重新下载并校验。解压后还要执行 `node verify-handoff.cjs .` 检查整个清单；不要直接改 SHA、重建清单或跳过检查。

### MySQL 提示 `MYSQL_NOT_MIGRATED`？

目标缺少合法初始化快照，程序不会自动生成空业务库，也不会回退到本地 JSON。检查六个命名空间是否已按受控方案导入并验证。不要用测试快照填入生产，也不要重跑不适用的旧站迁移脚本；见[部署指南](DEPLOYMENT.md)。

### 为什么第二个 API / PM2 cluster 启不来？

当前 MySQL 适配层需要单写入进程，并持有 `GET_LOCK`。检查是否同时运行 systemd、宝塔 Node 项目、Docker 或 PM2。保留一个负责该库的 API 实例，不要通过删除保护锁实现多副本。

### 连接 MySQL 断开后为什么不自动切回 JSON？

这是数据一致性保护。MySQL 模式下 SQL 是唯一持久化来源，连接异常或提交结果不确定时服务停止读写。排除数据库/网络故障，确认单实例后重启，从 SQL 重新加载；启用旧 JSON 可能造成数据倒退。

### 只备份 MySQL 够吗？

不够。图片、私有材料、聊天附件、上传分片、证书背景和新增地图在持久文件目录，数据库保存关联信息。需要一致数据库备份、完整文件目录、原数据密钥、运行配置及可用版本；还应做恢复演练。

### 可以升级时重新生成 `DATA_HASH_SECRET` 吗？

已有数据不能随意更换。它参与敏感数据保护和身份关联，不是普通用户密码。迁移/升级沿用原值；新建完全空数据环境才生成新随机值。遗失时联系原环境负责人，不要硬改库或尝试伪造解密结果。

### 宝塔更新可直接运行包内 `update.sh` 吗？

不可以默认这样做。历史 `update.sh` / `mysql-baota-update.sh` 针对特定旧 JSON 站点的一次性迁移，不能用于通用新站安装或已使用 MySQL 的日常更新。先识别部署场景，再按[部署流程](DEPLOYMENT.md)执行。

## 账号、权限与学校认证

### 平台账号密码和学校官网密码一样吗？

这是两个独立账号体系。日常登录使用平台账户；学校 CAS/OIDC 用于登记和验证身份。后台修改平台密码不会修改学校密码，平台也不应要求学校密码作为普通资料提交。

### 后台录入人员后为什么仍需实名校验？

录入普通人员、授予运营权限和完成身份校验不是同一件事。由有权限的管理员按实际证明进行人工校验，或由用户完成正式学校认证。不要因为姓名相同、学号相似或角色为教职工就跳过身份判断。

### 手工补录的学籍资料能伪装成官网返回吗？

不能。资料来源应保持准确；学校未提供的字段、人工确认字段与统一认证返回字段需要区分。实际修订由有权限的流程完成并留痕，不通过浏览器缓存伪造已校验状态。

### 配置学校认证以后还是无法注册？

检查学校实际登记的 HTTPS callback/service、允许域名、协议、属性映射、可信 subject 和后台启用状态。配置检查通过不等于真实学校账号授权已通过。H5 注册还要求在发起注册的同一浏览器继续，不能把回跳链接拿到另一台设备换票。

### 微信/支付宝/App 里学校认证为什么被阻止？

当前非 H5 的安全回跳/设备绑定尚未完成，服务端会返回 `REGISTRATION_PLATFORM_BINDING_UNAVAILABLE`。请在正式 H5 同一浏览器中完成注册；仅填写 AppID 或打开旧 `VITE_SCHOOL_REGISTRATION_READY` 不会补齐安全流程。

### 新设备登录后，旧设备退出是否正常？

正常，当前采用单设备会话策略。相同设备的持久身份依赖本地存储；清理浏览器数据、无痕窗口、不同浏览器或原生端并不保证被识别为同一设备。服务端可撤销会话，不能承诺账号永远不会因改密、暂停或安全操作退出。

### 模块隐藏后用旧链接还能使用吗？

设计上不仅隐藏前后台入口，还应由服务端模块规则限制相关访问。遇到入口已隐藏但直接 API 仍允许业务操作的情况，应记录版本和具体路径作为问题报告；不要仅靠 CSS 隐藏按钮解决权限问题。

### 内部人员档案会显示给普通用户吗？

学校维护关系使用的内部备注、标签和跟进记录属于受控后台资料，不是前台公开简介。查看权限、修改权限和审计应一起验证；勿将内部备注放入公开个人资料字段。

## 地图、文件与多端

### 地图框中为什么显示首页？

通常是 `/api/v1/maps/viewer/index.html` 被静态站的 SPA 回退接管，返回了首页 HTML。检查 Nginx/Vite 的 `/api` 转发优先级和路径前缀，确保地图查看器、瓦片和字体由 API 提供。不要把地图错误当作“没有地图数据”。

### 内置地图是否包括全国、能否显示人员精确位置？

目前内置长沙及周边服务器地图资源，其他城市需后台继续导入。公开展示是城市级聚合，不是个人实时位置或家庭门牌。“服务器本地地图”不等于 App 自带全国离线包。

### App/小程序地图能和 H5 一样用吗？

当前不能做这种保证。H5 使用 iframe；非 H5 只有引导入口，并且地图辅助函数仍返回相对 URL，需补齐 HTTPS 外链或适配合规 web-view。具体阻碍列在[多端说明](MULTIPLATFORM.md)。

### 允许 500 MB 图片或 5 GB 文件，为什么仍上传失败？

这是业务总文件上限，不是所有终端的能力保证。还要检查登录状态、格式、分片请求、服务器配额、磁盘、超时和弱网；不要把 Nginx 单请求上限直接改成无限大。聊天大文件选择/下载目前以 H5 实现为准，非 H5 有明确限制。

### `build:app` 为什么没有生成 APK / IPA？

它只编译 App 资源，不生成签名安装包。Android/iOS 还需 HBuilderX 或对应原生工程、包名/Bundle ID、签名证书、权限配置和实机验收。微信/支付宝则应导入各自的 `dist/build/` 平台目录；参见[完整多端流程](MULTIPLATFORM.md)。

### 官网同步或企业名称自动补全没有结果？

官网结构、网络、来源地址或企业数据服务配置可能影响结果。检查后台状态和脱敏日志，区分未配置、未匹配与接口失败；保留人工填写/维护流程。不能用示例数据冒充学校官网或真实企业数据。

## 如何提交有效问题

提供：release/tag 或提交号、目标端/浏览器与版本、页面路径、复现步骤、预期/实际结果、脱敏错误码和必要截图。公开截图请遮挡真实人员信息；安全问题不要公开令牌或可复用攻击细节，按仓库的安全联系方式处理。
