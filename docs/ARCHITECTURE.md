# 架构与代码导航

湖财人由用户端、Web 管理后台和 API 服务构成。主交付形态是浏览器 H5；uni-app 另有小程序/App 构建入口，当前差异见[多端说明](MULTIPLATFORM.md)。本文说明现有代码，不将未来规划视为已实现能力。

## 1. 总体结构

```text
用户端：uni-app / Vue 3 ─┐
                        ├─ HTTPS / Nginx ─ 单实例 Fastify API
管理后台：Vue 3 / Vite ──┘                      │
                                ┌─────────────┼──────────────┐
                                │             │              │
                         MySQL 六命名空间  持久文件目录   外部集成
                         业务/会话/审计等   图片/聊天/地图 学校认证/官网等
```

前端路由、按钮和菜单控制用户体验；最终身份、权限、内容与模块开关由 API 校验。管理后台不直接连接数据库。

| 目录 / 文件 | 职责 |
| --- | --- |
| 根 `App.vue`、`main.js`、`pages.json`、`manifest.json` | uni-app 生命周期、页面和平台配置 |
| `pages/`、`components/`、`custom-tab-bar/` | 用户端页面、通用组件和导航 |
| `services/` | API 调用、登录、上传、聊天等客户端服务 |
| `utils/`、`config/` | 会话展示状态、导航、平台差异和客户端配置 |
| `admin/src/router.js`、`views/`、`components/` | 管理后台路由、界面和维护流程 |
| `server/src/index.js`、`app.js` | 服务启动/关闭、依赖组装、中间件和路由注册 |
| `server/src/storage/` | JSON 开发适配与 MySQL 正式持久化、快照完整性 |
| `server/src/accounts/`、`auth/`、`manual-verification/` | 平台账号、学校认证、密码/会话、人工审核、内部档案 |
| `server/src/business/`、`chat/`、`media/` | 内容与服务业务、对话、私有文件和图片分片 |
| `server/src/modules/`、`moderation/`、`audit/` | 模块开关、敏感词与审计 |
| `server/src/regions/`、`maps/`、`content/` | 行政区域、地图、官网内容 |
| `scripts/`、`test/`、`server/test/`、`admin/test/` | 构建、隔离验收、发布辅助与测试 |
| `deploy/handoff/` | 交付指南和占位部署模板，不含生产密钥 |

## 2. 请求与身份边界

用户端统一请求封装为 [services/http.js](../services/http.js)，管理后台使用 [admin/src/lib/api.js](../admin/src/lib/api.js)。常规 API 响应包含 `code`、`message`、`data`；浏览器/平台差异在客户端条件编译分支处理。

普通登录使用**平台账号密码**，与学校统一认证的密码分开。令牌、账号状态、初始密码要求、设备标识和会话撤销由服务端决定；客户端缓存不能自行把人员升级为已实名或管理员。

学校认证用于新用户实名注册，服务端处理 CAS / OIDC 票据及属性映射，H5 事务使用同浏览器 HttpOnly Cookie 绑定。非 H5 安全回跳当前未闭环，服务端主动拒绝，不能绕过保护判断来开放注册。

人工审核是另一个受权限控制的身份来源，不等同于学校自动接口已经校验。普通平台用户、运营账号、实名状态、后台授权、组织/企业管理权限是不同概念，不应仅根据页面上的姓名或人员类型授权。

## 3. 业务模块与后台操作

- `accounts/` 管理人员录入/导入、去重、密码、校友编号、人工校验及校内维护档案。内部档案与前台公开个人资料分开，访问和修改走管理权限。
- `business/` 承载组织、活动、校园墙、企业/招聘、返校、公益/证书、服务申请等流程。通用资源定义与专门业务校验并用。
- `chat/` 管理单聊、群聊、固定学籍群、成员/管理员和文件票据，`media/` 处理私有材料与图片分片。
- `modules/` 将模块目录、前后台入口映射和接口禁用规则集中管理；关闭不是删除原有业务数据。
- `moderation/` 提供敏感词校验；`audit/` 保存请求和业务操作元信息，依赖精确可信代理设置推导来源 IP。
- `content/` 负责官网来源抓取、解析与同步；网站变化或网络问题会影响结果，不能由前端静态页保证长期有效。

一般新增能力需要同时检查：API 授权、数据约束、审计、模块映射、前后台入口、异常状态和测试，不能只新增一个页面。

## 4. MySQL 如何保存现有业务

正式设置 `DATABASE_DRIVER=mysql` 后，MySQL 是唯一业务持久化来源；连接或完整性错误不会静默回退到 JSON。

| 命名空间 | 数据范围 |
| --- | --- |
| `application` | 平台账号、身份及主要业务状态 |
| `chat` | 对话、群成员、消息和聊天文件相关元信息 |
| `image-transfers` | 图片分片上传任务状态 |
| `audit` | 操作与请求审计 |
| `regions` | 行政区域维护数据 |
| `content` | 官网同步内容状态 |

每个命名空间使用 `*_meta`、`*_collections`、`*_records` 三张表。业务记录逐条落行，记录内容使用 JSON 列保留嵌套字段，同时维护稳定键、顺序和 SHA；**不是把整个数据库塞进一个巨大 JSON 字段**。

启动时加载经完整校验的内存读取快照，业务事务串行提交 SQL，成功后才更新内存视图。现有同步读取接口决定了**单 API 写入进程**约束；MySQL `GET_LOCK` 用于阻止多个写入实例。

连接丢失、修订冲突或提交结果不确定时停用读写；健康检查验证数据库连接及锁归属。正常退出会排空已接受事务。不允许通过 SQL 手工修改业务字段绕过快照、SHA、审计和权限规则。

如果未来需要多副本部署，需要先改造业务查询/事务模型为合适的并发 SQL 架构，不能只去掉锁或把 PM2 改成 cluster。更多细节见 [MySQL 存储说明](../server/src/storage/README.md)。

## 5. 文件、上传与地图

数据库保存文件关联与权限元数据，二进制内容在受保护的持久目录：照片、私有材料、聊天附件、上传分片、证书背景和后续导入地图。**仅备份数据库无法恢复完整业务。**

图片与聊天文件采用分片协议，服务端控制文件上限、任务状态、登录身份和可下载范围。客户端允许较大的总文件，不代表单个 HTTP 请求也应同样大，也不代表每个平台都已实现同等文件能力。

长沙及周边内置地图资源、字体和查看器由 API 本地提供；H5 使用 iframe。后台上传的新地图进入持久文件目录。这里的“本地”是服务器本地托管，不是客户端已内置全国离线地图。公开地图显示城市级聚合，不提供个人实时定位。

## 6. 配置、发布与数据安全

- 客户端 `VITE_*` 构建变量可被终端用户读取，只能放公开 API 地址和界面参数。
- 服务端数据库、学校认证和数据保护密钥放受保护环境文件，配置逻辑集中在 `server/src/config.js`；详见[配置指南](CONFIGURATION.md)。
- `DATA_HASH_SECRET` 参与敏感数据保护和身份关联；已有数据升级必须沿用原值，不能当作普通可随时更换的口令。
- `server/src/index.js` 处理终止信号并关闭服务。生产使用单实例进程管理、持久文件卷和外部日志，版本代码不要原地覆盖。
- Release 交付代码和静态资源，不交付业务数据库、私有文件、真实账号密码或密钥。
- 软件包内保留的旧专站迁移脚本不是通用部署程序。正式使用按[部署指南](DEPLOYMENT.md)判定场景并校验文件。

## 7. 验证入口

根 `package.json` 提供 `validate`、`client:test`、`admin:test`、`server:test` 和构建命令。单元测试与结构检查不等于所有外部接口、平台真机或生产数据已验收。

真实 MySQL 测试需要显式的隔离测试库和重置许可，会删除该测试库的适配表，禁止指向正式库。多端、文件、学校回调、授权和备份恢复需要各自记录验收依据。

开始开发见 [DEVELOPMENT.md](DEVELOPMENT.md)，查看配置见 [CONFIGURATION.md](CONFIGURATION.md)，故障排查见 [FAQ.md](FAQ.md)。
