此包用于交付正式环境部署人员，包含完整项目源码、测试源码、已构建前台 / 后台、Linux 服务依赖及部署模板。**不包含生产数据库、用户材料、聊天附件、真实账号密码或服务器密钥。** 它是软件交付，不代表收到包后可直接空库一键启动。

## 使用顺序

1. 核对外层包旁的 `.sha256` 文件，将 ZIP 解压到全新空目录后，在该目录执行 `node verify-handoff.cjs .`；它会核验 `handoff-manifest.json` 中全部文件的大小、SHA 和清单（包括内部运行包）。任何不匹配立即停止，不跳过校验或重新生成清单。
2. 区分“承接原正式环境”“已有 MySQL 更新”和“完全空白新站”。先完成数据、密钥与管理员交接，再安排维护窗口。
3. 在新目录解压运行文件：

   ```sh
   mkdir release
   tar -xzf runtime/hufe-20260916-public-sanitized.tar.gz -C release
   ```

4. 按 `deployment/正式环境部署说明.md` 配置 MySQL、持久目录、单进程 API 和 Nginx；验证通过后开放流量。

## 必须知道

- 推荐 Node.js 22、MySQL 8.4；只允许单 API 写入进程，不能 PM2 cluster / 多副本写同库。
- 六个 MySQL 数据命名空间均须完整初始化 / 迁移并验证。当前程序不会自动创建空业务库。
- 当前没有通用的生产空库首管理员初始化 CLI。继承现有正式账号，或由正式学校 SSO 授权完成首管理员流程；没有数据且没有学校 SSO 时先请维护方提供受审计的初始化方案。
- 不运行 `create-dev-*` 或 QA 脚本初始化生产账号。此包没有默认可用管理员口令。
- 已有数据必须沿用原 `DATA_HASH_SECRET`，同时完整迁移私有文件；更换密钥会破坏解密和身份关联。
- 运行包内 `update.sh` / 源码内 `mysql-baota-update.sh` 仅适用于特定旧 JSON 站点的一次性迁移，不适用于新服务器，也不适用于已迁移 MySQL 的站点。
- 网站目录只放前后台构建成品，绝不放整个交付包、源码、数据库或环境配置。
- 本次成品为浏览器 H5 与后台；移动原生 App / 小程序需独立构建、配置和验收。
