# 数据与凭证另行交接清单

软件包可以交给部署人员；以下项目不能混入公开软件包，由原正式环境负责人核实授权后通过受控加密渠道交接。不要用本地演示数据替代正式数据。

## 搬迁 / 升级前必须确认

- [ ] 原正式环境当前版本、实际数据库名称、MySQL 版本、运行方式和 API 端口。
- [ ] 停写时间、备份时间、恢复点、谁批准切换以及失败时联系人。
- [ ] 完整 MySQL 备份，或六份同一停写窗口导出的快照：application / chat / image-transfers / audit / regions / content。
- [ ] 备份文件 SHA-256、六命名空间完整性结果，账号和主要业务记录数量；文件可解压 / 可恢复验证。
- [ ] 全部持久文件目录：聊天文件及分片、照片、人工认证材料、企业材料、相册、证书背景、后台上传地图及其他已存在文件；不挑选式只复制公开照片。
- [ ] 原 `DATA_HASH_SECRET` 原值（必须保留），以及当前其他会话 / 集成配置。
- [ ] 数据库应用用户访问方式和最小授权；数据库 root 或管理员凭据仅给负责数据库恢复的人员，不给应用。
- [ ] 学校 CAS / OIDC 登记信息、允许域名、回调、身份属性映射、正式管理员 subject / 角色授权；OIDC client secret 如有则单独保密。
- [ ] 域名 DNS 管理权限、TLS 证书 / 私钥、自动续期方式、Nginx 站点配置与代理拓扑。
- [ ] 现有正式超级管理员可登录确认。管理员的密码由本人或安全渠道处理，不通过数据库明文导出（系统保存的是密码哈希）。
- [ ] 自定义模块开关、内部人员档案和权限等保留在正式数据库内；无须从浏览器手工复制。
- [ ] 备份保留期限与访问权限，私有数据不进入网站根目录 / 工单附件 / 公共网盘。

## 不应交付或执行

- 不提供默认通用账号、批量重置口令或开发演示登录入口。
- 不把 `.local-runtime/`、`server/data/` 的本机业务副本、测试 MySQL 库或浏览器令牌整体打包。
- 不将真实密钥填回 `runtime.env.example` 再发普通附件。
- 不清空失败迁移的目标库强制重试；先保存现场并确认新目标。
- 对外开放写入后，不恢复旧 JSON 或旧 SQL 快照覆盖新增数据。

若正式环境仅更新代码，仍须做切换前备份；数据和凭据可以继续保存在现有受保护位置，无需为了“交接”重新传播一份。
