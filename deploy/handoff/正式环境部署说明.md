# 湖财人完整版部署交接说明

本说明面向 Linux / 宝塔部署人员。交付包含程序及已构建网页，不等于包含线上业务数据、账号密码或服务器密钥。先阅读交付根目录 `README.md` 和文件校验清单。源码在 `source/`，说明与模板在 `deployment/`。公开版运行文件为 `runtime/hufe-20260916-public-sanitized.tar.gz`，保留原业务程序及依赖，仅脱敏历史工具并重建清单；请使用公开版独立 SHA，不在包内追加日志或编辑文件。

在新工作目录解开运行包（目标 `release/` 必须尚不存在）：

```sh
mkdir release
tar -xzf runtime/hufe-20260916-public-sanitized.tar.gz -C release
```

解包后应有 `release/frontend/`、`release/admin/`、`release/server/`、`release/server-dependencies.tar.gz` 和 `release/release-manifest.json`。后文的 `release/` 均指此目录。包内 `update.sh` 是特定历史站点的 JSON → MySQL 迁移脚本，**不要为了普通部署运行它**。

学校中文名：湖南财政经济学院。英文名：Hunan College of Finance and Economics。校徽、英文名及许可素材随程序提供；现有 HUFE 账号编号、接口标识和域名不因此重命名。

## 一、先确定部署类型

| 场景 | 正确处理 |
| --- | --- |
| 全新服务器承接现有正式系统 | 在旧站停写窗口内备份并转移 MySQL、完整文件目录及原密钥，再启动新站。 |
| 已使用 MySQL 的站点更新程序 | 保留同一个数据库、文件目录和密钥，停旧 API 后以新版启动，验证后开放流量。不得导入旧 JSON。 |
| 完全新建、没有历史数据的站点 | 需要显式准备并导入六份合法的初始快照，以及正式首管理员初始化方案；当前包没有通用一键空库建站工具。不要仅启动服务期待系统自动建库。 |
| 指定旧 JSON 站点迁移到 MySQL | 必须由了解该站路径、容器、备份和流量切换方式的人员审核迁移方案。包内 `mysql-baota-update.sh` / `update.sh` 是特定旧站的一次性脚本，不是通用部署脚本。 |

**不可直接运行** `local-*`、`*-qa-*`、`create-dev-*`、历史 `baota-update-*` 等开发、验收或专站脚本。不可把本机演示数据库、测试账号和缓存作为正式数据。先核对运行包类型，再执行命令。

## 二、运行条件

- Linux，建议本次已验证的 Node.js 22 与 MySQL 8.4；Nginx 提供 HTTPS 和静态网页。
- Node API **只运行一个写入进程**。不使用 PM2 cluster、多 worker、双 API 并行或多个副本写同库。存储层持有 MySQL `GET_LOCK`，第二个写入进程会被拒绝。
- MySQL 使用独立库和专用应用用户，字符集 `utf8mb4`，业务表为 InnoDB。不使用 root 运行应用，不开放 MySQL 到公网。
- 运行查询需要该库的 SELECT / INSERT / UPDATE / DELETE；初始化快照导入另需要 CREATE / REFERENCES。应用没有跨库授权要求，不需要全局超级权限。
- 内存与磁盘按实际账号、聊天和上传量评估。六个命名空间在启动时加载内存；容量规划不能只按压缩包大小估计。聊天默认配额为 20 GiB，另需为照片、地图、备份和临时分片留空间。
- 前台 / 后台产物已构建，无须在正式机安装前端开发依赖。Linux 服务依赖归档必须与当前 `server/package.json` / 锁文件一致。不要使用 macOS 本机 `node_modules`。
- HTTPS 域名、证书、DNS 已配置。学校 SSO 若启用，需要学校正式登记回调和属性映射，程序部署不等于学校认证接口自动接通。

## 三、建议目录与配置

```text
/opt/hufe-platform/
  releases/<版本>/server/       # Node 源码与 Linux node_modules，只读代码
  current -> releases/<版本>/  # 停机窗口中切换，不覆盖正在运行的代码
  shared/runtime.env           # 权限 0600/0640，只交付给授权部署人员
  shared/data/                 # 可写、持久化，不放网站目录
  backups/<时间>/              # 私有备份，不放网站目录
/www/wwwroot/your-domain/      # 只放前台静态构建文件
  admin/                      # 只放后台静态构建文件
```

将 `runtime.env.example` 复制到受保护的 `shared/runtime.env`，替换所有占位符。原生 Node 同机部署可采用示例回环地址；容器部署须重新核对 HOST、MYSQL_HOST、数据路径与精确可信代理 CIDR，不能直接照抄原生模板。

`DATA_HASH_SECRET` 用于身份去重、学校认证配置、学号和会话等敏感数据保护。**已有数据搬迁或升级必须沿用原值**；改变会导致解密或身份关联失效，不是普通改密码操作。新建空数据环境才生成新随机密钥。数据库密码和各集成密钥均通过安全渠道另行交接，包内不带真实值。

虽然 MySQL 模式不把业务写回 `application-data.json`，`DATA_FILE` 的父目录仍决定 `chat/`、`maps/` 等文件存放位置。`MEDIA_DIR` 包括证件、企业材料、校园墙、相册、证书背景等；必须完整保留私有目录及其权限。内置长沙地图在 `server/src/maps/builtin/`；后台上传的地图另在持久目录 `maps/`。IP 归属库在运行包 `server/ip-region/`，若使用完整源码直接运行，须先核对该目录或设置正确的 `AUDIT_GEO_DIR`。

## 四、数据库与首个管理员

### 现有 MySQL 站点

从原站安全迁移数据库、持久文件和运行密钥。数据库内现有账号、密码哈希、管理员授权和业务记录保留，**本包不提供通用默认用户名 / 密码**。

推荐在维护窗口停止写入，再做一致备份：MySQL 完整逻辑备份、六命名空间快照、`shared/data`、运行环境和当前版本清单。MySQL CLI 凭证放私有配置文件，不要通过 `-p明文密码` 写进命令历史。备份包含个人资料和聊天记录，禁止放到公开下载路径或普通软件交付包内。

存储适配层的六命名空间为：`application`、`chat`、`image-transfers`、`audit`、`regions`、`content`。每个命名空间三张表，具有完整快照 SHA 校验。不要直接修改 JSON 列、哈希或修订号，也不要把 `server/db/*.sql` 的历史业务设计稿当成当前 MySQL 适配层初始化脚本执行。

需要按快照迁移时，旧站停写后逐一导出至新的私有目录，再在**独立空目标库**逐一导入 / 校验。以下路径是示意，必须替换；命令工作目录为该版 `server/`：

```sh
node --env-file=/secure/source.env src/cli/mysql-data.js export --namespace application --file /secure/new-backup/application.json
node --env-file=/secure/target.env src/cli/mysql-data.js import --namespace application --file /secure/new-backup/application.json
node --env-file=/secure/target.env src/cli/mysql-data.js verify --namespace application --file /secure/new-backup/application.json
```

对其余五个命名空间分别执行同样流程。`export` 不覆盖已有文件，`import` 不覆盖非空命名空间，`verify` 只读。在线分别导出六份数据并不保证跨命名空间属于同一业务时点，正式搬迁仍应停写。导入失败保留现场，禁止清库强行重试。

### 完全新建站点的明确边界

MySQL 启动要求已有合法快照，缺少时返回 `MYSQL_NOT_MIGRATED`，不会自动创建空业务库。当前没有面向生产的通用 `bootstrap-admin` CLI；`create-dev-admin.js` 明确禁止 MySQL 和 production，不能切成 development 来绕过。

若已有合法初始化快照且学校 SSO 已正式接通，可在受控初始化阶段使用学校认证：配置 `SSO_MANAGED_IN_ADMIN=false`、学校登记的 CAS/OIDC 信息，并将**学校返回的稳定 subject** 精确列入 `ADMIN_SUBJECTS`，或使用学校专门分配的可信管理员角色。该身份完成学校校验和平台注册后，注册逻辑会带入管理员资格。平台用户名不是学校 subject；不要把普通“教职工”广泛设为管理员角色。完成首管理员登录后，再通过后台配置 / 检查 / 发布学校认证，并依据实际配置切回后台管理模式。

**若既没有既有正式数据，也没有已接通的学校认证，需先由项目维护方交付受审计的生产初始化方案后再开放站点。** 人工认证本身需要有权限的审核员，不能解决“没有首管理员”的问题。本说明不伪造账号、不附带默认口令、不声称该缺口已由一键脚本补齐。

## 五、安装程序（原生 Linux 示例）

1. 校验外层压缩包 SHA-256，并按交付清单验证运行包。解压到新的版本目录，不能覆盖现有版本或先删除原站。
2. 只将运行包的 `server/` 放到 `/opt/hufe-platform/releases/<版本>/server/`。将匹配的 `server-dependencies.tar.gz` 解压到该 `server/`，解压后应为 `server/node_modules/`，不是多套一层目录。归档应仅包含常规依赖文件，部署前先列目录检查路径。依赖解压使用局部 `umask 022`，不要改变环境密钥 / 备份的私有权限：`(umask 022; tar -xzf /绝对路径/release/server-dependencies.tar.gz --no-same-owner --no-same-permissions -C /opt/hufe-platform/releases/版本/server)`。此处 GNU tar 参数用于目标 Linux。
3. 由部署人员创建专用低权限用户 `hufe`，代码归部署账户所有并供 `hufe` 读取，持久数据目录只允许应用用户写入。不要对整个程序或数据执行 `chmod -R 777`。
4. 先配置目标 MySQL、导入 / 恢复并校验六命名空间，再填写受保护环境文件。保留原数据密钥。
5. 核对模板的 Node 安装路径。安装 `hufe-api.service.example` 时去掉 `.example`，检查后执行 `systemctl daemon-reload`。在维护窗口确保旧 API 已停止，再 `systemctl enable --now hufe-api`。不要与原 Docker API 或 PM2 进程同时启动。
6. 先在本机检查 `curl --fail http://127.0.0.1:8787/health`，应返回 MySQL 就绪。用 `journalctl -u hufe-api` 查看经过脱敏的应用错误；不要把完整环境文件输出到日志。
7. 将 `release/frontend/` **内容**复制到静态站根目录；将 `release/admin/` **内容**复制到静态站根的 `admin/`。源码、依赖、SQL、配置、私有文件和压缩包不进入网站目录。
8. 合并 `nginx-site.conf.example` 到目标站点，替换域名、证书路径、端口和目录。检查 HTTPS 证书，执行 `nginx -t`（宝塔通常为 `/www/server/nginx/sbin/nginx -t`），成功后再重载。不要覆盖宝塔全局配置或别的站点。

本说明提供流程与模板，不是已替目标服务器执行安装。Docker 部署可采用 Node.js 22 镜像，但必须单实例，源代码只读、数据目录单独可写、端口仅绑定回环、MySQL 使用私网；在只读 `/app` 下挂载 `/app/data` 前，发布代码中必须已存在该挂载点。不要用历史站点脚本代替适配新服务器。

## 六、上线验收

- `/` 和 `/admin/` 正常显示新版校徽和英文名，桌面 / 手机宽度无主要操作遮挡。
- `/health` 成功且 `database.driver` 为 `mysql`；数据库故障应停止服务，不回退本地 JSON。
- 匿名访问 `/api/v1/admin/audit-logs` 返回 401；不能公开读取人员档案、聊天记录、证件材料或运行配置。
- 由已授权管理员实际登录；账号、权限、校友编号、数据数量与迁移前一致。不要以登录其他人的账号来代替验收。
- 学校认证入口与登记回调一致；完成一次真实授权测试，不能只凭配置检查认定学校已接通。
- 模块管理关闭后前后台入口隐藏，直接接口 / 旧链接不可绕过；重新开启后恢复。
- 人员档案备注和跟进记录保存后刷新仍存在，前台个人资料不显示内部备注。
- 图片 / 聊天文件用应用分片上传，测试下载权限；20 MiB 的 Nginx 单请求限制不等于 20 MiB 文件上限。实际大文件受文件配额、服务器空间和应用规则约束。
- 地图必须出现真实地图而非嵌入前台首页；`/api/v1/maps/viewer/index.html` 由 API 返回，不能被 SPA fallback 接管。
- 做一次服务重启后再检查业务数据、会话策略、文件访问、审计健康及数据库状态。

本包已构建交付的是浏览器 H5 和管理后台；原生 App / 微信小程序 / 支付宝小程序需各平台配置、构建和单独验收，不代表已发布。

## 七、备份与回退

保留至少：本次包 SHA、上一个可启动版本、数据库一致备份、全部持久文件、原环境密钥和 Nginx 配置。备份需要可恢复演练，不只是生成文件。

上线前失败可保持维护窗口、停候选 API 后恢复原版本。对外开放写入后，新数据已进入 MySQL，**禁止直接启用旧 JSON 或覆盖旧数据库快照**。回退前先冻结写入并备份当前数据库，确认旧代码能读取当前结构后才能回退代码；不兼容时先解决迁移问题。日志应在 release 目录外，避免破坏发布清单和只读代码目录。

收到包但缺少正式数据 / 原密钥 / 管理员授权时，请向原环境负责人通过安全渠道单独获取；不能从软件包推测、重置或伪造这些信息。
